## Important failure paths and bounded-work limits

`analogWrite()` falls back to pinMode(OUTPUT) plus a binary digital level if a pin has no PWM mapping **or** its PWM device is not ready, and discards the PWM setter status. Above half-scale the fallback can be HIGH. Later MotorGate must prevent an initialization/API failure from becoming sustained full duty; checked native status and fail-closed output initialization need real boundary tests. This source finding does not authorize a particular HAL implementation before P2 or change R1/R6.

P0.4 still requires **on-board** max/p99 tick jitter for 60 seconds, GPIO timings, unconnected four-pin QTR timeout-path duration, analogRead duration, and I2C timing when the named IMU exists. Host timings/mocks are not substitutes. A synchronous 10 us charge plus a possible 1500 us discharge already exceeds 1000 us period and 800 us execution ceiling before overhead. Source support for interrupts is a possible research direction, not approval to reuse stale readings or alter B4/B16 semantics.

Suggested benchmark records: exact board/core/loader/library versions and firmware revision; build flags; clock config; sample counts; raw cycle/microsecond deltas or bounded histogram; min/max/p99; missed deadlines; GPIO/ADC/I2C errors; test conditions and external instrumentation. Read logs after timing capture where possible, so Bridge printing does not silently change what is being measured. Full robot worst-case tick remains a separate P2 five-minute measurement including faults/timeouts.

## Additional Wire API observation relevant to future G6 work

The inspected [Wire.cpp][wire] maps Wire1 to I2C4, supports 100 kHz/400 kHz/1 MHz via setClock, calls synchronous `i2c_write` and `i2c_read`, and ignores the `stopBit` argument in endTransmission/requestFrom. No per-transaction timeout was established by inspecting this wrapper. Library compatibility, repeated-start needs, and bounded fault behavior must be proved for the actual IMU and installed Zephyr I2C driver; do not substitute a throughput calculation for timeout/WCET evidence.

## Release 1.0.0 cross-check

For the coordinator's prospective package pin, tag [`1.0.0`](https://github.com/arduino/ArduinoCore-zephyr/tree/1.0.0) resolves to commit **79b3f1afdad455f55e4a25030953617152c0227c**. Release and current-main source archives were compared byte-for-byte in memory, with command exit 0. `zephyrCommon.cpp`, `wiring_analog.cpp`, `wiring_digital.cpp`, `WInterrupts.cpp`, UNO Q overlay/conf, matrix header and `loader/matrix.inc` are identical. Their G2 source observations therefore apply to both snapshots. The release's west manifest names the same mutable Zephyr branch; the actual release-built Zephyr revision/config must still be recovered from installed package artifacts, not inferred from today's branch head.

Release [`Wire.cpp`](https://github.com/arduino/ArduinoCore-zephyr/blob/79b3f1afdad455f55e4a25030953617152c0227c/libraries/Wire/Wire.cpp) **differs** from main: main adds a requested-size capacity check and resets a nonempty receive buffer before requestFrom. Both snapshots retain synchronous I2C calls and ignore stopBit. This is why main must not be treated as an installed release. Verify the chosen IMU library against 1.0.0 explicitly before any dependency claim.

P0 matrix/timing sketch API evidence: release `micros()` has exactly the source algorithm described above; release `matrixGrayscaleWrite()` copies a fixed 104 bytes and sets a flag without heap allocation or waiting. Matrix initialization starts a 10 us periodic ISR, so timing-only versus matrix-active tests must be labeled separately. The source checks authorize no claim of 800 us worst-case runtime, successful target compilation, or completed P0 round trip.
