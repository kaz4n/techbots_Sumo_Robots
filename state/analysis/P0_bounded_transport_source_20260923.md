# P0 bounded transport source check — 23 September 2026

## Outcome

**No existing bounded, allocation-free post-setup Monitor/Bridge/RPClite send API was found in the pinned stack.** The asynchronous Zephyr UART alternative is disabled in the installed loader configuration reported by the coordinator. A small, transmit-only UART interrupt adapter using the existing router protocol is technically plausible; it is **a proposed implementation, not a verified complete path or an approval**. It requires exclusive peripheral ownership and bounded failure handling. It cannot share the active Bridge serial instance or call its blocking write functions.

The narrow candidate does not require a new library, replacement router, general RPC engine or new wire protocol. If ownership/export inspection fails, or satisfying it requires replacing the loader/dependencies, the result for the present constraints remains blocked. P0's real Monitor counter round trip remains incomplete; a RAM counter is not equivalent.

## Lower UART primitives and ownership

1. **Polling output is unsuitable.** The official API explicitly describes blocking output. The inspected STM32 implementation spins until transmit space exists without a deadline. [API](https://github.com/arduino/zephyr/blob/1743741760ee5d2d58da50d504855d43f9f8e826/include/zephyr/drivers/uart.h#L383-L400), [driver](https://github.com/arduino/zephyr/blob/1743741760ee5d2d58da50d504855d43f9f8e826/drivers/serial/uart_stm32.c#L771-L793).
2. **IRQ FIFO output is a usable primitive, with conditions.** Both FIFO fill and transmit-ready checking require UART interrupt context; their results from ordinary sketch context are documented undefined. The inspected STM32 fill loop is bounded by the supplied byte count and returns when no space exists. A single call with a fixed maximum can therefore support a bounded callback; this is source reasoning, not measured WCET. [API](https://github.com/arduino/zephyr/blob/1743741760ee5d2d58da50d504855d43f9f8e826/include/zephyr/drivers/uart.h#L460-L479), [ready contract](https://github.com/arduino/zephyr/blob/1743741760ee5d2d58da50d504855d43f9f8e826/include/zephyr/drivers/uart.h#L564-L583), [driver](https://github.com/arduino/zephyr/blob/1743741760ee5d2d58da50d504855d43f9f8e826/drivers/serial/uart_stm32.c#L927-L953).
3. **Asynchronous transmit is not an installed option.** The API provides immediate-return submission with completion callbacks, but its timeout applies to flow control. Configuration/device support are prerequisites. The installed config receipt above disables it. Zephyr also forbids combining asynchronous and interrupt APIs on one peripheral; callbacks are exclusive by default. [API](https://github.com/arduino/zephyr/blob/1743741760ee5d2d58da50d504855d43f9f8e826/include/zephyr/drivers/uart.h#L740-L777), [ownership warning](https://github.com/arduino/zephyr/blob/1743741760ee5d2d58da50d504855d43f9f8e826/doc/hardware/peripherals/uart.rst#L31-L38), [Kconfig](https://github.com/arduino/zephyr/blob/1743741760ee5d2d58da50d504855d43f9f8e826/drivers/serial/Kconfig#L66-L91).
4. **Bridge and raw UART cannot both own transmission.** Core serial setup installs its own IRQ callback. Bridge's global instance targets the devicetree router serial. The UNO Q overlay maps that role to internal LPUART1. A raw adapter must establish exclusive ownership rather than overwrite an active callback or interleave packets with Bridge traffic. [core setup](https://github.com/arduino/ArduinoCore-zephyr/blob/1.0.0/cores/arduino/zephyrSerial.cpp#L54-L75), [singleton](https://github.com/arduino-libraries/Arduino_RouterBridge/blob/0.4.3/src/singletons.cpp#L14-L23), [overlay](https://github.com/arduino/ArduinoCore-zephyr/blob/1.0.0/variants/arduino_uno_q_stm32u585xx/arduino_uno_q_stm32u585xx.overlay#L390-L391).

## Existing protocol and initialization implications

The official router documents MessagePack-RPC notification shape as a three-element array. The specific output is conceptually `[2, "mon/write", [text]]`, where text may be a MessagePack string or binary value. Its notification route invokes the registered internal handler with a discarded result; no MCU response wait is necessary. The monitor handler accepts exactly one string/binary argument. These are existing protocol semantics, not a proposed new protocol. Sources: [protocol README](https://github.com/arduino/arduino-router/blob/v0.10.0/msgpackrpc/README.md), [notification routing](https://github.com/arduino/arduino-router/blob/v0.10.0/internal/msgpackrouter/router.go#L188-L215), [monitor handler](https://github.com/arduino/arduino-router/blob/v0.10.0/internal/monitorapi/monitor-api.go#L117-L156).

Inference from router source: registering MCU methods, a reset request, a router-version query and a monitor-connected query are not prerequisites for dispatching this built-in output method. The existing Bridge performs those calls for its own lifecycle/compatibility needs. This does not prove delivery: the router must already be listening, a receiving monitor client must be attached, and a notification has no acknowledgment. With no monitor client, output can be discarded; a stalled single client has no router-side write deadline. Source: [registration](https://github.com/arduino/arduino-router/blob/v0.10.0/internal/monitorapi/monitor-api.go#L30-L43), [router reset scope](https://github.com/arduino/arduino-router/blob/v0.10.0/internal/msgpackrouter/router.go#L134-L142), [monitor writes](https://github.com/arduino/arduino-router/blob/v0.10.0/internal/monitorapi/monitor-api.go#L132-L156).

Framing is the serialized MessagePack value stream, not newline-delimited raw UART text. Dropping the tail of a partly transmitted message then starting another can corrupt decoding. A bounded adapter therefore needs a fixed packet buffer, a cursor retained until completion, bounded refusal/drop behavior before submission, and a defined terminal fault/recovery rule for partial transmission. The router decoder consumes full values from the stream; source reading does not establish a universal resynchronization guarantee. [decoder](https://github.com/arduino/arduino-router/blob/v0.10.0/msgpackrpc/connection.go#L155-L251).

## Smallest candidate and remaining evidence

Candidate only: one fixed-capacity packet slot containing the existing notification format; a try-submit operation that immediately refuses while busy; one exclusively owned UART ISR that attempts a fixed maximum byte count per invocation and disables TX interrupts when idle/error; a bounded service deadline; no dynamic objects, inbound RPC handler, retry-until-ready loop, or Bridge/Monitor/ZephyrSerial write. This is a dedicated output adapter, not an existing library feature.

Before treating it as available, the coordinator must establish the installed loader's exact device mapping, callback ownership, exported API/device access, startup/readiness ordering and linked loop-hook behavior. No callback replacement, strong hook override, loader rebuild, dependency patch or pin reassignment is justified by this note. Then independent tests must establish exact framing, buffer refusal, partial progress, zero progress, duplicate/missing completion and terminal failure behavior; target compilation and inert physical receive/failure/timing evidence remain separate. Output failure must leave control independent of Linux and must never authorize motors. No board action or test was performed by this author.
