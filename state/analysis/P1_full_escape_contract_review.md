# Full Escape: bounded specification/public-header review

2026-09-22 Asia/Dubai. Reused separate reviewer context; specification/public headers only, no implementation read, code edit, test or hardware operation. This is contract advice, not a fresh phase-gate review.
Sources: BEHAVIOR B2/B4/B7/B8, accepted D-020/D-044/D-047..D-050, delegated D-051, P1 prompt, edge.h/motion.h and the SearchSide/SearchContext public contract.
No contradiction blocks the proposed wrapper. Record the following material choices explicitly under D-051 before implementation/test authors depend on them.

1. Freshness: each step consumes one new complete confirmed low-four-bit line observation. The caller owns freshness, as for Classifier/Guard; do not turn a cached reading into another replacement opportunity. Update the previous-mask baseline on every admitted observation, including clearing, and retain it across replacement starts.
2. Priority: retain existing reset-only faults; closed permission before an escape creates no new line fault. Once permitted, all-white/three-white faults precede selection/replanning and payload checks. Otherwise use D-049 pushed-out selection, then the ordinary row table; initial entry costs zero budget.
3. Phase boundaries: snapshot entry phase and declared pivot direction before stepping the old script. Use those only to classify newly white bits: during PIVOT, its turning-side bits; other active phases, any new bit. Do not derive pivot direction from governed duty signs.
4. Completion remains an independent D-050 trigger: if no earlier replacement occurred, step the old script and handle resulting DONE with persistent white on that same observation. Entry-phase classification must not suppress this condition at PIVOT-to-DONE boundaries. Permit at most one replacement start per observation, with all new timers anchored to that observation rather than backdated.
5. Keep the replacement budget across every phase and script restart: three successful replacement starts are allowed; the fourth request faults before motion. Only actual all-black plus script-DONE exit or explicit reset clears the budget. A failed replacement start faults; it must not silently continue the old request.
6. Permission loss while an escape episode is active, including DONE-but-white waiting, should latch a wrapper fault with zero requests, immediate brake and inhibition until reset. Later permission restoration cannot resume a stale script. Preserve Guard's existing gated escape_required semantics and independent veto contract rather than changing its locked component API.
7. Actual exit requires all black and completed script on the same current observation. Emit the exit indication once. Publish fresh inward-heading evidence only if current imu_ok is true and the actual current yaw is finite; unavailable yaw must not be replaced by a last-known value. No valid exit heading means no new heading/timestamp evidence, so callers must not refresh an older record's age.
8. Heading validation follows existing row/motion contracts: finite initial/last-known heading when starting a row; current healthy nonfinite yaw faults when consumed, including an otherwise successful exit; current yaw while imu_ok=false is ignored. Normal IMU loss remains bounded fallback, not itself an escape fault.
9. Validate context only when the selected branch consumes it. D-049 consumes both previously applied final duties as a pair when centered-front plus rear-white makes qualification relevant; require both finite and within [-1,1], then apply strict >0. Unused duty/context payloads must not defeat an otherwise valid branch. Validate selected history direction only when used by head-on/both-rear selection; absent history uses the approved default, distinct from an invalid consumed enum.
10. All faults return zero and inhibit motor permission; ordinary requests retain RowExecutor's profile, B7 fallback/timeout and B6 downstream governor obligations. New wrapper policy does not amend established locked RowExecutor/Guard/motion behavior.

Required regressions: all 16 masks and D-049 duty/centering boundaries; entry-phase deadline ties plus completion-and-white; turn-side/opposite-side additions; clear/reassertion; simultaneous bits; exact third/fourth requests; black before completion; permission loss and restoration; reset; healthy/unavailable/nonfinite exit yaw; invalid consumed versus ignored unused values; mirrors and time wrap. Existing locked tests remain unchanged.
