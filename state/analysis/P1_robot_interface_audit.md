# Robot interface dependencies: bounded public-contract audit

2026-09-22 Asia/Dubai. Reused separate reviewer context. Read specifications and public core headers only; no implementation read, build, test or hardware operation. Recommendations are not implementation findings or a phase-gate verdict.
Sources: BEHAVIOR B0/B2/B3/B4/B5/B9/B11/B12/B13/B14/B15, D-018/D-024/D-027/D-028/D-032/D-045..D-051/D-054, types.h and all existing module public contracts.
Full Escape is being implemented independently under committed contract 5360c80. The following items concern the subsequent production Robot interface, not that batch's approval.

1. Fusion/stall sequencing is the principal contract dependency. Fusion.observe samples once; commit must consume that observation exactly once against the final selected state. Stall.Detector needs ATTACK/contact/contact_started before deciding whether to replace ATTACK with REFLANK. A provisional ATTACK commit followed by a REFLANK commit violates the existing single-use contract. Define the resolution before Robot code; a small read-only current-contact candidate preview for stall, followed by one final commit, is preferable to duplicating Contact's latch policy in Robot. Specify detector history when the candidate causes REFLANK or is preempted by edge/STOP.
2. One Governor.step per Robot tick is essential: it advances battery filtering and slew history. Specify stall and D-049 Escape predicates against the preceding applied final electrical duties, rather than running the governor speculatively. Current Inputs has no applied-duty feedback. Either add explicit caller-supplied feedback or define an enforceable contract that final emitted duties are exactly what MotorGate applied; inhibited hardware must report zero. A core request alone is not physical application evidence.
3. Choose one authoritative line input. Inputs currently exposes raw RC times and line_mask, while Classifier consumes fresh raw samples and Escape consumes fresh confirmed masks. State which field Robot consumes, who classifies and how gated Services receives that same observation. Do not independently resample/debounce for services, Fusion, qualification or escape.
4. Specify one genuinely fresh Robot observation per tick and an explicit duplicate/stale-call contract. Fusion caches immediate repeated timestamps, but Escape, FrontQualification and Classifier do not. Robot must not forward cached Fusion data as another fresh observation or replay one-call events. Freshness remains a caller/HAL obligation, not a host-test hardware claim.
5. Countdown Lifecycle needs raw pre-bias gyro, confirmed opponents and confirmed lines before its motor-gate return. Inputs.gyro_z_dps is currently ambiguous about bias. Expose the actual raw field/previous-bias source and propagate accepted calibration and heading_reset_requested to the app. Every Fusion observation, including gated ticks if observed, still needs one ineligible-state commit to clear contact correctly.
6. GO coordinate ownership must be explicit. Lifecycle returns a heading-reset request on the same tick that motion becomes permitted, while Inputs already contains that tick's yaw. Specify atomic rebasing of heading and all world-bearing, inward and motion-reference history before same-tick opener/escape entry; merely asking HAL to reset next tick changes coordinates underneath captured targets. Do not fabricate a healthy yaw when IMU is unavailable.
7. Robot owns state/script lifecycle: run gate/edge priorities first, start an executor once on entry, reset NormalPerception on script entry/preemption, then count exactly the current exit observation once under D-045. Preserve D-046 loss-tick brake even when routing to SEARCH/DEFEND_TURN; do not call the new state's moving step until the next tick in that case. Invalid consumed script results need an explicit inhibited Robot fault disposition under D-051 rather than accidental fallback routing.
8. Centralize history ownership without changing component contracts. SearchSide supplies the shared D-041/D-047 side. Convert BearingMemory timestamps into non-resurrecting ages for SearchContext/SwingContext; track front rising-side recency, actual accepted swing starts and limiter history across script reset. Escape inward evidence is an exit pulse only. Re-flank recent-edge side must remain invalid for unknown/bilateral geometry; do not infer it from the pivot command without a documented mapping.
9. WAIT is still absent from the inspected opener public header. Select and record the bounded policy in P1_wait_contract_audit.md under D-051, then commit its interface before independent tests/implementation. Existing Direct/Flank contracts already cover the other modes. This is a finite missing behavior, not a reason to redesign all openers.
10. B0/B15 output transport remains intentionally deferred in Outputs. Prefer a bounded per-tick event batch plus frame/diagnostic values owned by the returned Robot result; leave the existing 4096-event EventBuffer with its documented recorder owner. Define exact metadata codes, deterministic same-tick event order and a proven batch capacity/explicit rejection status. Do not add another unbounded queue or discard event/PackStatus errors silently.
11. Record actual pulses once: qualified START_RELEASE, GO, first final nonzero enabled duty, every committed state change, EDGE, rising CONTACT, STALL decision, accepted REFLANK BACK plus returned SWING/TURN_IN entries, PHANTOM_SET and newly declared faults. Reflank's same-tick phase order is BACK then SWING then TURN_IN. Specify which current mask EDGE carries and distinguish new edges, persistent escape and replacements; repeated fault/status levels are not repeated events by default.
12. Frame cadence and B14 measured execution duration need caller/Robot ownership. Current tick duration is known only after step returns; do not pretend it is an input already measured for that call. A separate supplied-duration update or explicitly identified previous-tick report can feed TickStatistics. Preserve saturation, frame clamping/invalid status, final duties and calibration/stuck/phantom flags. No host result proves the separate robot WCET requirement.
13. B13 mode/service UI and B14 remaining warnings need explicit scope. Existing button contracts implement release/cancel/STOP, not the complete short-MODE/long-MODE service menu. Define logical mode selection and safe reset/IDLE lifecycle without inventing ADC decoding. QTR-stuck warning, IDLE battery source and hardware reset-cause evidence remain separate documented dependencies; none may suppress line safety or invent a new motor policy silently.

Recommended sequence: finish frozen Escape, settle WAIT, then commit the smallest Robot input/result/lifecycle and contact/stall contracts with a scenario matrix. Preserve all established locked tests and keep HAL acquisition, physical application, recorder transport and human gate evidence distinct.
