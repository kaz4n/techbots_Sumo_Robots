## Concrete implementation interface

The installed include combination is `Arduino.h`, `wiring_private.h`, and
`<zephyr/drivers/gpio.h>` (the latter is already included by Arduino.h:16).
`wiring_private.h:23-25` defines
`zephyr::arduino::arduino_pins[]`, a constexpr `gpio_dt_spec` table generated by
`DT_FOREACH_PROP_ELEM_SEP(DT_PATH(zephyr_user), digital_pin_gpios,
GPIO_DT_SPEC_GET_BY_IDX, (, ))`. Select it using the proposed
`config::OPP_INPUT_PINS[i]`; validate the index against the table size before
indexing. Keep all pin assignments in config.h; do not duplicate numeric
assignments in the implementation. `digitalPinToPortDevice` and
`digitalPinToPinIndex` exist in zephyrCommon.cpp, but omit the DT flags needed
for validation. There is no need to invent a getGPIO API or another unimplemented
Port interface.

Recommended direct calls and exact installed declarations:

```cpp
bool gpio_is_ready_dt(const gpio_dt_spec* spec); // gpio.h:854-857, inline
int gpio_pin_configure_dt(const gpio_dt_spec* spec,
                          gpio_flags_t extra_flags); // :1066-1071, inline
int gpio_pin_get_raw(const device* port, gpio_pin_t pin); // :1565-1580, inline
```

Validate `spec.dt_flags == 0`, pin range/mask and non-null port before use.
Readiness calls device_is_ready; it observes successful existing device
initialization and does not initialize/reconfigure it. A false result must be
reported without calling configure/read. GPIOA/B/C are non-deferred boot devices;
do not add device_init or retry loops. Retain every configure int result and
only mark that pin configured after result 0. For reads, accept only 0 or 1;
preserve negative errno and report unexpected positive values as invalid.
Do not reuse an older successful bit/validity result after a later failure.
Seven fixed iterations suffice; no delay, heap, peripheral wait or Bridge is
needed. Capture micros before/after the pass if duration metadata is required;
`zephyrCommon.cpp:17-23` reads the cycle counter and converts to 32-bit usec.

The native wrapper updates a pin's invert bit before the configure callback
returns; configure failure is not a transactional rollback. A failed pin must
remain invalid even if metadata partially changed. gpio_pin_get_raw ignores
invert metadata by design. Installed pinMode/digitalRead are unsuitable here:
pinMode discards errors and digitalRead maps all negative errors to LOW.

| GPIOC, ordinal 91 | 0x0801c01c; base 0x42020800; pin mask 65535 |
| z_impl_device_is_ready | Thumb 0x08019e6f |
| driver pin_configure | Thumb 0x08019151 |
| driver port_get_raw | Thumb 0x080190bd |

Readiness body 0x08019e6e-0x08019e82 checks null and device state bytes with no
calls, stores or peripheral read. Configuration body 0x08019150-0x08019220 has
finite flag branches and the pad helper at 0x080178bc-0x080179c4. GPIO_INPUT
does not take output-level stores or alternate-function pin selection. The
pad helper does bounded register read/modify/write without loops or locks.
The read body 0x080190bc-0x080190c6 reads IDR at base+0x10 and returns 0.
PM/PM_DEVICE and assertions are disabled in the installed configuration.
No discovered normal or error branch waits, allocates, sleeps or retries.
Instruction-path boundedness is not measured WCET under interrupts or bus stalls.

`gpio_pin_get_raw` calls gpio_port_get_raw, checks its int return, then selects
one physical bit. Public generated syscall wrappers inline the implementation
dispatch. Crucially, loader LLEXT entries named z_impl_gpio_pin_configure and
z_impl_gpio_port_get_raw have address 0. Actual target compilation must inline
these wrappers through the nonzero device API; do not call those zero exports
directly. Inspect final relocation tables and retained native class methods,
not just compile exit status. Using the complete installed arduino_pins table
may retain additional device relocations depending on optimization; audit all
retained imports in the actual target image, not only ordinals 89-91.

The installed local GPIO driver normally returns success after an IDR read;
checking errno does not detect broken wires, floating pins, lost mux ownership,
stuck sensor output, wrong voltages, or every hardware fault. Fake-header error
tests demonstrate software propagation, not an injected MCU fault experiment.

## Ownership exclusions and integration limits

- SPI is SPI2 (overlay:394; SPI.cpp:137-154). Its default pinctrl uses PB13,
  PB14, PB15 and PB9 (DT:12717-12728); SPI.begin reapplies that state
  (SPI.cpp:116-128). This conflicts with all three front opponent pads and
  the proposed MOTOR_EN pad. No SPI/SPI2 initialization is allowed alongside
  these owners without a separately resolved design.
- Wire2 is I2C3 (overlay:393; Wire.cpp:253-274), whose default state uses PC0
  and PC1 (overlay:32-37). Wire2.begin reapplies it (Wire.cpp:59-65). Wire1
  is I2C4 on PD12/PD13, distinct from these seven pins.
- Direct analogRead(A2..A5), analogWrite(D11..D13), digital reconfiguration or
  IRQ registration on the opponent pins would compete with this driver.
- PWM1's full Arduino state includes PA11/PB15/PB13/PB14, and ADC1's full
  Arduino state includes all A0..A5. These lists alone do not establish that
  a call on D5/A0 remuxes every listed pin. Installed wiring_analog.cpp:129,
  :239 calls init_dev_apply_channel_pinctrl; zephyrPinctrl.cpp:123-166 validates
  the selected ordinal and calls pinctrl_configure_pins on exactly one pin.
  Their default/sleep states are empty. Preserve this per-channel distinction
  when implementing the future motor/ADC backends.
- Native configure and its invert bitmap use read/modify/write without mutual
  exclusion. Serialize setup and exclude concurrent reconfiguration on GPIOA,
  GPIOB and GPIOC, including other pins sharing the same registers/metadata.
- The candidate must audit linked constructors, static threads, initVariant,
  selected loop hook and runtime services for ownership/blocking. This source
  audit does not bless unbuilt application hooks or the inherited Bridge path.
