# D222 implementation and evidence owner

This directory owns future exclusive commissioning compile outputs. The generic
caller derives each child name from the selected profile, explicit motor flag,
full source digest and attempt token. Do not rerun a consumed owner or copy old
results into a fresh owner. Failed command streams and checked target artifacts
remain evidence; compilation never grants upload or motor-run permission.

The new policy privately executes the same five checked D213 snapshots and changes
only the closed selector flags and result identity. The new caller privately loads
the hash-checked D214 caller. It reuses source mapping/staging, command execution,
one compiler/query, bounded transfer/wait, metadata verification, artifact payload
transfer and independent closing. It adds exact request parsing, deterministic
owners, reviewed-HEAD byte admission and profile-labelled receipts. Its run method
requires Python -B without the old one-off -X pycache_prefix invocation detail.

The new remote adapter verifies its complete nine-role source bundle before exec,
then reuses D214 descriptor reads and three independent artifact/loader/TLS closing
checks. The host validates the new profile/motor identity before passing the rest
of the unchanged layout/report through D214's full validator. No source or tunable
in src/ and no historical policy/caller were modified.

Static authoring finding: the originally proposed long owner exceeded the existing
48-character stage-token guard. The normative contract now hashes the full source
digest, NUL and full attempt into a 12-hex suffix and retains both full identities
in the manifest and receipts. Existing owners always fail exclusive creation.
The D222 tester also caught initial remote ordering that checked the primitive
before other supplied source identities; this was corrected before test execution.

Host tests, independent review and any actual target compilation are pending.
No upload, motor energization, hardware acceptance or phase gate is represented.
